# Hotel Augusto Website Implementation Plan

**Goal:** Build an original, carefully art-directed hotel website for Hotel Augusto, Varanasi, with WhatsApp enquiries and a clear path to a future booking engine.

**Architecture:** Next.js App Router static server components own factual content and route metadata. Small client components own menu, motion, gallery, FAQs, and booking enquiry interaction. One typed content module supplies hotel contact and room data.

**Tech stack:** Next.js 16.4, strict TypeScript, Tailwind v4, Framer Motion, lucide-react, local font assets, Playwright; Vercel-ready in sin1.

## Brief and assumptions
- Premium execution for a real hotel client; truthful positioning, not unsupported luxury claims.
- Visitors include couples, families, and pilgrims planning a Varanasi stay.
- English website, mobile first. No rates or inventory until a booking engine is supplied.
- WhatsApp is an enquiry channel, not a confirmed reservation. Do not send messages automatically.
- Static delivery keeps operation simple and cheap; no stored personal data, payment processing, authentication, analytics or database at this stage.
- Digiocular maintains the source; a private independent Git repository is required. No production domain changes are part of this task.
- Public phone is found; WhatsApp use requested for confirmation from client.

## Art direction and decisions
- An editorial city hotel: warm paper, terracotta, confident serif typography, large candid property photographs, small wayfinding details and a slow, deliberate visual rhythm.
- Use genuine destination imagery as a city introduction, explicitly differentiated from hotel spaces. Prefer property images for rooms and actual guest decisions.
- Layouts alternate full-width imagery, asymmetric text/image spreads and roomy editorial lists; avoid repeated card rows.
- Mobile gets its own typography scale, crops, direct navigation and fixed booking access. Avoid horizontal scroll and oversized fixed UI.
- No simulated availability, fabricated ratings, stock hotel rooms, artificial video, heavy WebGL, loading gates or scroll hijacking.
- Awwwards references are recorded separately. Reuse useful composition principles without cloning a site.
- UI Pro dataset inspected. Chosen typography pair: Magazine Style (Libre Bodoni / Public Sans). Adapt warm neutral tokens for the hotel. Generated glassmorphism and navy/gold proposal rejected because it violates the explicit brief.

4. Visual/browser/accessibility/performance/security verification and refinements — 25 points.

## Implementation and acceptance
1. Collect official/Google/OTA evidence and licensed destination photography. Save `research/` ledgers; conflicts are excluded from marketing copy.
2. Create `content/hotel.ts`, room data, image data and typed booking adapter. Unit-test dates, room preselection and URL encoding where meaningful.
3. Create global tokens, layout metadata, header/footer, motion wrapper and reusable editorial elements.
4. Build home with city-led hero, hotel introduction, room previews, dining, neighbourhood, gallery preview and booking close.
5. Build functional `/rooms`, `/rooms/[slug]`, `/varanasi`, `/gallery`, `/contact`, and `/privacy` routes.
6. Verify enquiry form requires valid future dates, check-out after check-in, and party details; it opens a prepared WhatsApp draft and never implies confirmation.
7. Run lint, typecheck, unit checks and production build. Start the server and inspect all routes at 390px and 1440px; also sweep 360/768/1024/1920px.
8. Test navigation, menu Escape/focus, room links, gallery filters/lightbox keyboard, reduced motion, scroll restoration, images, outgoing links and metadata. Use axe and record console errors.
9. Review screenshots and fix visual weaknesses. Record any remaining factual/asset/contact limitations honestly.
10. Produce source README and a handoff report with a generator-created DOCX twin; commit the completed source. Measure C/D free space and remove only positively identified task scratch files within verified paths.
